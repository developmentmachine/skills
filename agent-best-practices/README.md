# Agent 最佳实践分享素材

**题目：** 让 Agent 可靠交付：从「会用」到「用好」  
**时长：** 60 分钟  
**听众：** 已经用过 Agent，但经验从刚入门到长期使用不等

这不是提示词技巧课，也不是某个平台的功能说明。

课程围绕一条工作主线展开：

> 目标 → 上下文 → 行动 → 验证 → 沉淀

听众离开时，应该能把一项工作交给 Agent，并回答：

1. 为什么这项任务适合或不适合 Agent？
2. Agent 开始前，目标、范围、事实来源和完成标准是否明确？
3. Agent 实际查看了什么、改了什么、运行了什么？
4. 哪些证据证明结果正确，哪些内容仍未验证？
5. 这套做法应该留在本次对话，还是沉淀成 Rule、Skill、Subagent 或 Automation？

## 教学原则

- 使用同一个案例贯穿全课，不为初学者和资深用户各讲一套概念。
- 主页面只放所有人都要掌握的动作；进阶要求放在练习加分项。
- 不把 Agent 的自述当证据。证据来自文件、测试、diff、日志和权威系统。
- 不承诺 Agent 一定遵循指令。区分「看到了」「照做了」「结果正确」。
- Skill 放在课程结尾：先把流程跑通，再决定是否沉淀。

## 主演示

案例是一条「重复提交仍被接受」的问题。

演示仓库已经包含一个失败测试。现场要求 Agent：

1. 先读任务和相关文件；
2. 运行测试，确认修改前确实失败；
3. 做最小修改；
4. 再运行测试；
5. 展示 diff；
6. 报告仍未验证的内容。

主持人不要预先承诺 Agent 会一次成功。失败时正好演示如何缩小任务、补充事实或重新开始。
