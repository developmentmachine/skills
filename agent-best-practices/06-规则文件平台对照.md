# Agent 规则文件平台对照

核对日期：2026-10-05。产品行为可能变化，授课前应重新检查官方文档。

## 先记住结论

- 项目级 `AGENTS.md` 已经被 Codex、Cursor、Hermes 和 GitHub Copilot 原生支持。
- Gemini CLI 默认读取 `GEMINI.md`，但可以配置为读取 `AGENTS.md`。
- Claude Code 默认只读取 `CLAUDE.md`，可以在其中用 `@AGENTS.md` 引入公共规则。
- 用户级全局规则没有统一目录。`~/.agents/` 主要是多款产品共同使用的 Skill 目录，不是通用的全局 `AGENTS.md` 目录。

不要把「文件存在」等同于「当前 Agent 已加载」。文件名、搜索范围、合并顺序和覆盖规则都由宿主产品决定。

## 推荐的跨工具项目结构

```text
repo/
├── AGENTS.md          # 跨工具共享的项目规则
├── CLAUDE.md          # Claude Code 入口，内容可为 @AGENTS.md
└── src/
    └── AGENTS.md      # 仅在确认所用产品支持嵌套规则时使用
```

Gemini CLI 可以在 `settings.json` 中加入：

```json
{
  "context": {
    "fileName": ["AGENTS.md", "GEMINI.md"]
  }
}
```

公共规则只写一份。`CLAUDE.md`、`GEMINI.md` 或产品专属规则只补充该产品确实需要的差异，不要复制整份内容，否则更新后容易互相冲突。

## Codex

- 原生读取 `AGENTS.md`。
- 用户级默认规则：`~/.codex/AGENTS.md`。
- 项目中从仓库根向当前工作目录逐层读取 `AGENTS.md`；更接近当前目录的内容更具体。
- 同一目录可以用 `AGENTS.override.md` 覆盖 `AGENTS.md`。
- `/init` 可以生成当前目录的起始文件。

官方文档：[Custom instructions with AGENTS.md](https://developers.openai.com/codex/guides/agents-md)

## Cursor

- 原生读取项目根和子目录中的 `AGENTS.md`。
- 父目录和嵌套规则会组合，更具体的子目录规则优先。
- 需要路径匹配、手动启用或元数据时，使用 `.cursor/rules/*.mdc`。
- 跨项目个人默认值使用 Cursor 的 User Rules；官方文档没有把 `~/.agents/AGENTS.md` 定义为全局入口。

官方文档：[Rules](https://cursor.com/docs/rules)

## Gemini CLI

- 默认上下文文件是 `GEMINI.md`。
- 用户级默认规则：`~/.gemini/GEMINI.md`。
- 项目根、工作区路径和访问到的子目录可以分层发现 `GEMINI.md`。
- `context.fileName` 可以改成一个文件名或文件名列表，因此可以接入 `AGENTS.md`。
- `/memory show` 用于查看已拼接的上下文，修改文件后可用 `/memory reload` 重新加载。

官方文档：[Provide context with GEMINI.md files](https://geminicli.com/docs/cli/gemini-md/)

## Hermes Agent

- 原生读取项目中的 `AGENTS.md`，并逐步发现子目录规则。
- Hermes 专属的 `.hermes.md` 或 `HERMES.md` 优先级更高。
- 项目上下文类型采用「首个匹配类型生效」：存在更高优先级的 Hermes 文件时，不能假设 `AGENTS.md` 仍会同时加载。
- 全局身份与表达风格使用 `$HERMES_HOME/SOUL.md`；它不等于项目规则。
- `AGENTS.override.md` 可用于个人、目录级覆盖，通常应加入忽略列表。

官方文档：[Context Files](https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files)

## GitHub Copilot

- Copilot Agent 支持仓库中的一个或多个 `AGENTS.md`，离目标文件最近的规则优先。
- Copilot 专属的仓库级规则放在 `.github/copilot-instructions.md`。
- 路径级专属规则放在 `.github/instructions/**/*.instructions.md`。
- Copilot CLI 的用户级规则放在 `~/.copilot/copilot-instructions.md`。
- Cloud Agent、Code Review、IDE 和 CLI 支持面不完全相同，授课或落地时要说明具体产品形态。

官方文档：[Adding repository custom instructions](https://docs.github.com/copilot/customizing-copilot/adding-repository-custom-instructions-for-github-copilot)

## Claude Code

- Claude Code 默认读取 `CLAUDE.md`，不直接读取 `AGENTS.md`。
- 项目中可以创建 `CLAUDE.md`，用下面一行复用公共规则：

```markdown
@AGENTS.md
```

- 用户级默认规则放在 `~/.claude/CLAUDE.md`。
- 项目级还可以使用 `./CLAUDE.md` 或 `./.claude/CLAUDE.md`。

官方文档：[How Claude remembers your project](https://code.claude.com/docs/en/claude-md)

## 用户级规则为什么不能只放一处

当前没有一份所有产品都会自动读取的用户级规则文件：

```text
Codex       ~/.codex/AGENTS.md
Gemini CLI  ~/.gemini/GEMINI.md
Claude Code ~/.claude/CLAUDE.md
Copilot CLI ~/.copilot/copilot-instructions.md
Hermes      $HERMES_HOME/SOUL.md（身份与风格）
Cursor      User Rules
```

如果需要跨产品维护，应该先确定一份自己的权威源，再通过各产品支持的引用、同步或生成方式接入。同步机制必须可检查；不要假设软链接、导入语法或云端同步在所有产品中都有效。

## 验收加载结果

配置完成后至少检查：

1. 当前产品是否真的发现了目标文件；
2. 项目根、子目录和用户层的合并顺序；
3. 是否因为专属文件而跳过公共 `AGENTS.md`；
4. 同一规则是否被重复加载；
5. 云端 Agent、远程会话和本机是否读取相同文件；
6. 仓库自带规则是否来自可信来源。

规则文件只是模型输入的一部分，不是强制执行机制。真正不能违反的权限和安全边界，应由沙箱、权限、审批、Hook 或确定性程序落实。
