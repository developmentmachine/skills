# 分享大纲

**题目：** 让 Agent 可靠交付：从「会用」到「用好」  
**时长：** 60 分钟  
**前提：** 听众至少使用过一次能读文件或调用工具的 Agent

## 一句话主张

用好 Agent，不是把提示词写得更长，而是设计一个目标明确、行动受控、结果可验证的工作闭环。

## 听众离开时要能做

1. 用「可验证、可访问、可控制」判断任务是否适合交给 Agent。
2. 用六项任务契约说明目标、范围、事实来源、约束、完成标准和审批点。
3. 在执行过程中区分观察、计划、行动和检查。
4. 不相信「已经完成」的自述，使用测试、diff、来源和日志验收。
5. 失败时选择补事实、缩范围、回退改动或新开干净上下文。
6. 只把已经验证过的重复流程沉淀为 Rule、Skill、Subagent 或 Automation。

## 主线

### 1. 为什么「会聊天」不等于「会交付」（4 分钟）

投影第 1–2 页。

展示一段措辞完整的「已修复」回复，但没有修改前证据、测试和 diff。请听众判断能否合并。

结论：回复质量不能证明任务完成。

### 2. Agent 的最小心智模型（6 分钟）

投影第 3–4 页。

Agent 由模型、指令与上下文、工具、状态、执行循环和宿主控制共同组成。模型决定下一步，工具读写真实世界，验证决定是否结束。

再用三个条件判断是否该使用 Agent：

- 结果能够被验证；
- 必要事实和工具能够被访问；
- 错误的行动能够被限制、审批或回退。

### 3. 开始前先签任务契约（8 分钟）

投影第 5 页。

任务契约包括：

1. 目标；
2. 范围；
3. 事实与来源；
4. 约束和非目标；
5. 完成标准；
6. 审批点与停止条件。

这六项不是固定提示词，而是检查任务是否可执行。

### 4. 怎样给上下文、能力和自主权（7 分钟）

投影第 6–8 页。

- 事实优先来自仓库、测试、日志和业务系统。
- Prompt 管本次任务，Rule 管持续约束，Skill 管重复流程。
- 工具和 MCP 提供行动能力，Memory 只保存可能过期的跨会话状态。
- Subagent 用于隔离或并行任务，Automation 决定何时自动启动。
- 高风险、不可逆或影响范围不清楚的动作必须保留审批点。

### 5. 端到端现场演示（12 分钟）

投影第 9–10 页，按 [05-现场练习.md](05-现场练习.md) 操作。

使用 `examples/login-submit/`：

1. 先确认问题；
2. 运行失败测试；
3. 查看相关实现；
4. 做最小修改；
5. 再运行测试；
6. 查看 diff；
7. 报告未验证内容。

主演示证明的是完整证据链，不是证明某一种提示词永远有效。

### 6. 验收与失败恢复（6 分钟）

投影第 11–12 页。

验收四问：

1. 它依据了什么事实？
2. 它实际做了什么？
3. 什么证据证明结果正确？
4. 哪些内容仍未验证？

失败恢复顺序：

1. 停止继续扩大改动；
2. 找出缺失事实或错误假设；
3. 缩小成一个可验证步骤；
4. 必要时回退并新开干净上下文。

### 7. 何时沉淀（4 分钟）

投影第 13 页。

同一做法真实成功过多次，输入输出稳定，失败边界清楚，才考虑沉淀。

不要把第一次对话直接包装成 Skill 或 Automation。

### 8. 分层练习与带走（10 分钟）

投影第 14–15 页。

基础任务：把一句模糊需求补成任务契约。

进阶任务：指出权限风险、事实来源、并行机会，以及哪些步骤不应自动化。

所有人最后都提交同一种答案：任务契约和验收证据。

其中 6 分钟写作、2 分钟讲评、2 分钟收束第 15 页。全课另留 3 分钟给转场或演示恢复，不安排新内容。

## 可删

- 45 分钟版本：删第 13 页，练习改为课后作业；主演示必须保留。
- 30 分钟版本：保留第 2、3、5、9–12、15 页。
- 不要为了省时间删除修改前失败证据、修改后测试或 diff；少了其中一项，主演示就不再是完整闭环。

## 不在主线讲

- 各平台 Skill 目录和字段差异；
- Plugin 的包格式；
- 模型排行榜；
- 通用的「万能提示词」；
- 没有验收标准的多 Agent 编排。
