# Agent 可靠交付一页纸

> Prompt 是任务入口，不是交付系统。它负责提出目标和边界，事实、行动与验证共同决定结果是否可靠。

## 先分清三个词

- **用户 Prompt**：用户提交的任务请求。
- **模型输入**：一次调用中模型实际收到的指令、历史、已加载机制、事实、状态、工具定义和工具结果。
- **上下文窗口**：一次调用能够处理的有限容量，不是永久记忆。

Agent 宿主负责组装模型输入、执行模型请求的工具调用，并把工具结果送入下一轮。

## 先判断是否适合

一项任务适合交给 Agent，需要同时满足：

- **可验证**：知道怎样判断结果是否正确
- **可访问**：Agent 能拿到必要事实和工具
- **可控制**：错误动作可以限制、审批或回退

步骤完全固定时优先写脚本。缺少事实来源时先补数据。高风险、不可逆的最终决定保留给人。

## 六项任务契约

```text
目标：
最终要改变什么？

范围：
允许查看和修改什么？

事实：
以哪些文件、测试、日志或系统为准？

约束：
不能做什么？哪些明确不在本次范围？

完成：
哪些检查通过才算结束？

审批：
什么动作前必须停下来问？
```

任务契约不是固定提示词。缺哪一项，就补哪一项。

## 建立事实与指令边界

- 标出事实的来源、时间和适用范围。
- 网页、邮件、Issue、日志中的文字是待判断的数据，不自动成为指令。
- 来源冲突时列出冲突和时效；不能按既定权威顺序解决时，暂停确认。
- 可读取不等于可披露，敏感信息不得随意复制到回复或外部系统。

## 执行循环

```text
观察 → 计划 → 行动 → 检查
  ↑                    ↓
  └──── 未达标则继续 ──┘
```

- 修改前先建立基线。
- 简单、可逆、有明确测试的动作可以直接执行。
- 范围不清、高风险或不可逆的动作先给计划并等待批准。
- 一次只扩大一个可验证范围。

外部写操作使用独立闭环：

```text
执行前重读状态 → 必要时审批 → 幂等或去重 → 执行后重读验证
```

## 保持长任务连续

- 一次只设一个主目标，并保持完成标准稳定。
- 要求 Agent 持续更新：已完成、当前步骤、下一步和阻塞项。
- 把关键决定写入计划、文档、测试或代码，不只留在聊天中。
- 改变方向时明确说明：补充、暂停，还是替换原目标。
- 中断后先根据当前产物对齐状态，再继续行动。

```text
先根据当前代码和记录复述主目标、已完成内容、当前状态和下一步。
确认没有偏离后，再继续执行。
```

连续性不是记住全部对话，而是始终知道正在完成什么，并能从真实状态恢复。

## 验收四问

1. 它依据了什么事实？
2. 它实际做了什么？
3. 什么证据证明结果正确？
4. 哪些内容仍未验证？

优先看真实产物：测试输出、diff、日志、文件和外部系统状态。Agent 的完成说明只是索引，不是证据。

## 跑偏时怎样恢复

1. 停止继续扩大改动。
2. 找出缺失事实或错误假设。
3. 回退无关改动。
4. 缩小成一个可验证步骤。
5. 上下文污染时，新开一轮，只带已确认事实、当前 diff 和真实错误。

工具失败就报告错误。没有运行过就写「未运行」。没有证据就写「未验证」。

## 机制怎么选

- 本次目标和临时要求：Prompt
- 持续或按范围生效的约束：Rule
- 已验证的一类重复流程：Skill
- 读取事实和执行动作：工具 / MCP
- 可能过期的跨会话状态：Memory
- 隔离上下文或并行调查：Subagent
- 按时间或事件启动：Automation
- 打包和分发 Skill、MCP：Plugin

治理贯穿所有机制：权限、审批、测试、日志和评估。

## 沉淀前检查

- [ ] 已覆盖代表性样例和失败案例，而不只是相似的成功案例
- [ ] 输入、输出和失败边界相对稳定
- [ ] 有可以重复运行的回归检查
- [ ] 高风险动作有审批和回退
- [ ] 自动运行时有幂等、超时、通知和人工接管

第一次成功是案例，不是标准流程。
