# Plugin 一页纸

## 和 skill、memory 的边界

做法用 skill。系统里此刻的数据和受控动作用 MCP。还没写进手册的跨对话事实用 memory。插件只在 skill 和 MCP 要一次装走时才需要。Memory 不放进 `plugin.json`。

## 它是什么

Plugin 是一个目录，用来把 skill 和 MCP 一次装走。Skill 仍是任务手册。MCP 提供实时数据、身份、权限和受控动作。

v1 的固定位置：

```text
my-plugin/
├── plugin.json
├── skills/<skill-name>/SKILL.md
├── mcp.json
└── com.example.client/
```

## 基础

最小清单：

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "hello-plugin"
}
```

`name`：1–64；`a-z`、`0-9`、`-`、`.`；首尾为字母或数字；不能有 `--` 或 `..`。

`skills/` 只发现直接子目录里的 `SKILL.md`。没有 `skills/` 或没有 `mcp.json` 都合法。

ChatGPT 与 Codex：在 Plugins 里安装，新开对话，直接说任务，或用 `@` 点名。Codex CLI 用 `/plugins`。IDE 扩展不提供插件。

一份 skill、只在当前项目用：不必打包。

## 进阶

| 放在 skill | 放在 MCP |
| --- | --- |
| 顺序、缺口处理、输出格式 | 连接、身份、工具、受控动作 |

`mcp.json` 每个服务必填 `type`：`stdio`、`streamable-http`，或可选的 `sse`。`command` 是单个可执行名或 `./` 路径，参数放 `args`。

| 变量 | 用途 |
| --- | --- |
| `${PLUGIN_ROOT}` | 包内只读文件 |
| `${PLUGIN_DATA}` | 可写状态，升级后保留 |

一条服务失败，其他服务和 skill 继续加载。`plugin.json` 缺必填字段时，整包拒绝。

## 高级

可移植的只有 skill 和 MCP。钩子、自定义界面、客户端开关放 `extensions.<反向域名>` 或同名顶层目录。

`plugin.json` 与 `mcp.json` 的 `$schema` 版本必须相同，否则停用 MCP、保留 skill。

密钥不写入 `headers` 或 `env`。包内路径以 `./` 开头，且不能解析到插件根外面。

规范不规定安装、市场、权限和沙箱。公开目录、工作区 marketplace、个人 marketplace 是产品自己的分发层。
