# Plugin 规范备查

投影用幻灯。这里收容易讲错的约束，依据是 [Agent Plugins 1.0.0](https://agent-plugins.org/specification)。产品行为另注出来源。

## 清单

允许的顶层字段只有：`$schema`、`name`、`version`、`description`、`author`、`homepage`、`repository`、`license`、`keywords`、`extensions`。

| 情况 | 客户端行为 |
| --- | --- |
| 未知顶层字段 | 报告并忽略，继续加载 |
| `extensions` 不是对象 | 报告并忽略该字段，继续加载 |
| 缺 `$schema` 或 `name`，类型不对，名字不合法，或其他字段类型不对 | 拒绝整包，不发现、不执行组件 |
| 不认识的 `$schema` 版本 | 拒绝整包 |

1.0.0 的 `$schema` 必须是 `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`。加载时不从网络拉取 schema。

`author` 只能有字符串字段 `name`、`email`、`url`。`version` 建议语义化，但写得不像语义化版本、主页不像 URL、许可证不像 SPDX，都不能单独作为拒绝理由。

名字：1–64；字符集 `a-z` `0-9` `-` `.`；首尾为字母或数字；禁止 `--` 和 `..`。合法例子：`my-plugin`、`acme.tools`。技能名仍然不能包含点，那是 Agent Skills 的规则。

## 版本

两个版本都在包上。插件里的 skill 遵守 [Agent Skills 规范](https://agentskills.io/specification)，没有单独的版本字段。`SKILL.md` 的 `metadata.version` 只是书目，不参与发现或加载。

| 字段 | 含义 |
| --- | --- |
| `$schema` | 包所针对的 Agent Plugins 规范版本。有 `mcp.json` 时必须同一版。对不上：停用 MCP，skill 继续。客户端不认识：拒绝整包 |
| `version` | 可选字符串。用途是更新检查和缓存新鲜度。客户端可以不读 |

`version` 建议语义化：主版本号是不兼容变更，次版本号是向后兼容的新行为，修订号是修正。不像语义化版本，不能单独作为拒绝理由。

加载的是客户端当前这份插件目录。规范没有版本选择器、锁文件或「当前激活版本」。`version` 不触发替换，也不证明包内文件与另一份不同。作者不改这个字符串，目录里的文件仍可以换掉。

规范不定义升级或降级步骤。替换发生时，包内文件换掉，`PLUGIN_DATA` 必须保留。升和降若由客户端提供，都是这次替换。安装、分发和更新界面不在可移植规范里。

## 发现

| 组件 | 位置 | 缺席时 |
| --- | --- | --- |
| Skill | `skills/<目录>/SKILL.md` | 不当作错误 |
| MCP | 根上的 `mcp.json` | 不当作错误 |

只检查 `skills/` 的直接子目录，不递归。`SKILL.md` 必须是普通文件。不合格的 skill 跳过，并继续其他 skill。

`skills` 若存在但不是目录，或 `mcp.json` 存在但不是普通文件：该组件类型无效，其他类型继续。

`plugin.json` 不能改这些位置，也不能内联组件。整个插件只有这一份可移植清单，没有第二个文件能覆盖它的核心字段。

## MCP

`mcp.json` 只有 `$schema` 和 `mcpServers`。`$schema` 为 `https://agent-plugins.org/schemas/1.0.0/mcp.schema.json`，且必须与 `plugin.json` 同一版本。空的 `mcpServers` 合法。

整份 `mcp.json` 无效、版本不支持或与清单版本不一致：停用该插件的 MCP，skill 继续。

单条 server 无效、传输不支持、或启动 / 连接 / 认证 / 握手失败：跳过该条，其他 server 和 skill 继续。没有「失败后改用另一种传输」。

支持 MCP 的客户端至少实现 `stdio` 或 `streamable-http` 之一，建议两者都实现。`sse` 可选。

### stdio

| 字段 | 要求 |
| --- | --- |
| `command` | 单个可执行 token。裸命令名，或 `./` 开头的包内路径。不做占位符替换 |
| `args` | 字符串数组，可选 |
| `env` | 字符串到字符串，可选。不能包含名为 `PLUGIN_ROOT` 或 `PLUGIN_DATA` 的项 |
| `cwd` | 可选。省略时用插件根。否则是 `./` 路径、`${PLUGIN_ROOT}` 或其子路径、`${PLUGIN_DATA}` 或其子路径 |

包内自带的可执行文件必须用 `./` 路径。不要依赖客户端是否用 `env` 里的 `PATH` 去解析裸命令。

### 远程

`url` 为绝对 HTTP(S)，不能带用户信息或片段。主机不是 `localhost` 或回环 IP 时必须是 HTTPS。

`headers` 的名和值都是可见的包数据。禁止在其中放凭据。同名头出现两次（仅大小写不同）无效。客户端为 HTTP、MCP 或授权生成的头，覆盖同名配置头。重定向到别的源之前，不能悄悄带上这些头。

v1 没有可移植的 OAuth 字段。授权交互和凭据存储由客户端负责。

## 变量

启动 stdio 子进程的客户端必须注入：

- `PLUGIN_ROOT`：插件根的绝对路径
- `PLUGIN_DATA`：该安装实例专用的可写目录，更新后保留，卸载时可以删除

先把配置里的 `env` 叠到客户端选择的基础环境上，再强制写这两个变量。

展开只发生在 `args` 的每个字符串、`env` 的值、`cwd`。一次替换，不递归。其他 `${...}` 保持原样。不展开 `command`、不展开 `env` 的键、不展开组件的固定路径。

`PLUGIN_DATA` 放依赖、缓存和生成物。`PLUGIN_ROOT` 引用随包文件。

## 路径安全

插件相对路径以 `./` 开头，解析后必须留在插件根内。`../` 以及不以 `./` 开头的相对路径，在被定义为路径的字段上不合法。

符号链接可以指向根内，解析到根外则拒绝。拒绝范围按最窄的一层：清单本身出根则整包拒绝；某个 skill 出根则跳过该 skill；某条 `command` 或 `cwd` 出根则该 server 无效。

这不沙箱子进程，也不限制运行时才传进来的路径。

## 扩展

`extensions` 的键是反向域名，值是对象。对应文件放在根下同名目录。客户端忽略未实现的名空间，且不校验其内部。

v1 不把钩子、命令、代理、规则、LSP 定义成可移植组件。OpenAI 文档里的钩子、自定义 UI、`.codex-plugin/` 兼容清单，属于该客户端的产品层。

## 产品层备忘（ChatGPT / Codex）

来源是 ChatGPT 与 OpenAI 的插件文档，不是 Agent Plugins 规范正文。

- 公开插件目录为 ChatGPT 与 Codex 共用。IDE 扩展不提供插件。
- 调用：新对话里直接描述任务，或 `@` 点名插件 / skill。CLI 用 `/plugins` 安装，装完新开一轮。
- `@plugin-creator` 默认生成 `.codex-plugin/plugin.json` 等兼容布局。可移植包要另写根上的 `plugin.json` 与带 `type` 的 `mcp.json`。
- OpenAI 专有字段放在根清单的 `extensions.com.openai`，不要写成可移植顶层字段。
- 插件钩子在云端编排的 ChatGPT Work 中不可用。网页安装不会部署钩子脚本。
- 非托管钩子按内容哈希信任后才运行。
- 仓库 marketplace：`.agents/plugins/marketplace.json`。个人 marketplace 在用户目录的对应位置。CLI：`codex plugin marketplace add`。
